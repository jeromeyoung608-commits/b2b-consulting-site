Executive Summary

A high-fidelity, enterprise-grade frontend prototype delivered as a zero-dependency single-page web app — pure native HTML, CSS and Vanilla JavaScript, no framework, no build step, no external network request.

The platform models the complete B2B consulting journey: a services breakdown, client proof, tiered pricing, a lead-capture CTA, and a full interactive booking modal with a working month calendar and time-slot picker. Unlike low-end page builders, the booking surface is real client-side state — the calendar navigates months, disables past dates, and commits a selected slot before the form submits.

A custom App-Runtime layer (app-runtime.js, v1.0.0) abstracts data access behind a swappable adapter, surfaces skeleton loading, and degrades gracefully through a recoverable error + retry component. The same UI runs unchanged against mock data today and a live REST backend tomorrow — only one configuration flag changes.

02

Core Features

Four capabilities distinguish this build from a template: each is implemented as deterministic logic, not decorative markup.

  • Interactive booking calendar & slot picker — a real month grid with prev/next navigation, past-date disabling and day selection, paired with a time-slot chooser. State is held client-side and committed before submit; this is a genuine datepicker, not a static image.
  • Data-driven services & pricing — service cards and the three pricing tiers are generated from structured data through the runtime, so content is rendered from a single source of truth, not hand-copied markup. Flipping the adapter to remote re-binds the same DOM with no template change.
  • Booking-modal state machine — open → pick date/slot → submit → success is an explicit, guarded progression; illegal back-steps and empty-slot submits are prevented by the flow logic itself.
  • Non-blocking toast feedback — demo notices (e.g. polite Legal / confirmation messages) use an in-page toast() rather than native alert(), so they work inside sandboxed preview iframes and under strict CSP without breaking the page.

Architecture & Code Standards

The runtime is the one piece of shared infrastructure. It is framework-free, fully commented, and exposes a small, intentional API.

// app-runtime.js — v1.0.0  (zero dependencies, pure Vanilla JS)
AppRuntime = {
  apiRequest(url, opts)      // Axios-shaped fetch: 8s timeout, Bearer token, typed ApiError
  dataAdapter               // the single seam:  mock <-> remote  (setMode)
    .request(endpoint, opts) // UI never touches fetch directly
    .setMode('mock' | 'remote')
  showLoading(host, label)  // skeleton state
  hideLoading(host)
  showError(host, msg, retry) // recoverable error + Retry button
  mount(host, boot, opts)    // lifecycle: skeleton -> request -> render / retry
  debounce(fn, ms)           // search / input coalescing
  throttle(fn, ms)           // resize broadcast guard
}

Pure Vanilla JS — no React, no Vue, no jQuery. Mock data lives inside the dataAdapter as the single source of truth and is rendered through DOM templates with event delegation. Because the data layer is isolated behind dataAdapter, a backend engineer only replaces one module to go live; the entire UI, loading and error behaviour stays intact.

  • Token-driven CSS — colours, spacing and radii are :root variables; no magic hex values scattered in rules.
  • Mobile-first — base styles target the phone; widen with @media (min-width:…).
  • Accessible — labelled inputs, visible focus, prefers-reduced-motion guards on heavy animation.
  • Commented business logic — booking flow, state transitions and timers carry clear explanations.
